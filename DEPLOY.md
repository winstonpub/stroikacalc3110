# Развёртывание сайта на GitHub Pages

По этой инструкции сайт будет открываться по адресу:

```
https://<ВАШ-ЛОГИН>.github.io/StroikaCalc/
```

Код от этого адреса не зависит: все картинки и страницы подключаются относительными ссылками, поэтому сайт одинаково работает и локально, и в подпапке `/StroikaCalc/`.
Имя страницы в адресе задаётся **именем репозитория** — создайте его ровно с названием `StroikaCalc`.

---

## Что уже готово в проекте

| Файл | Зачем нужен |
|---|---|
| `.github/workflows/deploy.yml` | Автоматическая сборка и публикация при каждом push в `main`. Ничего настраивать не нужно. |
| `public/.nojekyll` | Отключает лишнюю обработку файлов на GitHub Pages, чтобы ничего не пропадало. |
| `package-lock.json` | Нужен для команды `npm ci` в облачной сборке — версии библиотек всегда совпадут. |
| `dist/` | Готовая собранная версия сайта (создаётся командой `npm run build`, в Git не отправляется). |

## Вариант A. Через GitHub Desktop (без командной строки)

1. Зарегистрируйтесь или войдите на <https://github.com>.
2. Нажмите **New repository** и создайте репозиторий:
   - **Repository name:** `StroikaCalc` (именно так, с большой «S» и «C»);
   - **Visibility:** Public (бесплатная публикация Pages доступна для открытых репозиториев);
   - галочки «Add a README file», «Add .gitignore», «Choose a license» **не ставьте** — папка должна быть пустой.
3. Нажмите **Create repository** и скопируйте адрес вида `https://github.com/<логин>/StroikaCalc.git`.
4. Установите [GitHub Desktop](https://desktop.github.com), войдите в свой аккаунт.
5. Меню **File → Add local repository…** → выберите папку с проектом (ту, где лежат `package.json` и папка `src`).
   Если программа предложит создать репозиторий здесь — согласитесь и укажите название `StroikaCalc`.
6. В окне GitHub Desktop нажмите **Publish repository**:
   - Name: `StroikaCalc`;
   - снимите галочку «Keep this code private», если она стоит;
   - нажмите **Publish repository**.
7. Перейдите на сайт `https://github.com/<логин>/StroikaCalc` → вкладка **Actions**.
   Через 1–2 минуты появится зелёная галочка в запуске **Deploy to GitHub Pages**.
8. Откройте **Settings → Pages** и убедитесь, что в блоке **Build and deployment → Source** выбрано
   **GitHub Actions** (обычно включается само при первом запуске workflow).
9. Ваш сайт готов: <https://<логин>.github.io/StroikaCalc/>

## Вариант B. Через командную строку (Git)

Проект в этой папке уже инициализирован как Git-репозиторий и содержит первый коммит.
Осталось указать удалённый репозиторий и отправить код:

```bash
# 1. Проверьте, что вы в папке проекта (там, где лежит package.json)
# 2. Укажите своё имя и почту (они попадут в историю коммитов)
git config user.name "Ваше Имя"
git config user.email "your-email@example.com"

# 3. Свяжите локальный проект с созданным репозиторием StroikaCalc
git remote add origin https://github.com/<ВАШ-ЛОГИН>/StroikaCalc.git
#    если remote уже существует — замените адрес:
#    git remote set-url origin https://github.com/<ВАШ-ЛОГИН>/StroikaCalc.git

# 4. Отправьте код в ветку main
git branch -M main
git push -u origin main
```

Репозиторий `StroikaCalc` должен быть создан заранее и быть **пустым** (без README).
Если GitHub попросит пароль — используйте **Personal Access Token** вместо пароля
(Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token,
права `repo` и `workflow`).

После отправки откройте **Actions** в репозитории и дождитесь зелёной галочки,
затем проверьте **Settings → Pages → Source: GitHub Actions**.

## Как обновлять сайт

1. Внесите изменения в файлы проекта.
2. Проверьте сборку у себя на компьютере:
   ```bash
   npm install
   npm run build
   ```
3. Отправьте изменения в GitHub:
   ```bash
   git add .
   git commit -m "Обновил сайт"
   git push
   ```
4. GitHub Actions сам пересоберёт и опубликует новую версию (1–2 минуты).

Настройки из раздела «Администрирование» (бегущая строка, меню, подвал) публикуются
в Google-таблицу и обновляются **без** пересборки сайта — см. раздел README
«Общие настройки для всех пользователей». Для этого адрес веб-приложения Apps Script
вводится один раз на странице `#/admin` в блоке «Подключение к таблице».

## Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| Открывается страница 404 | В **Settings → Pages → Source** не выбран **GitHub Actions**. Выберите его и перезапустите workflow (Actions → Deploy to GitHub Pages → Re-run jobs). |
| Адрес сайта другой | Адрес всегда содержит имя репозитория. Если репозиторий назван иначе (например `calcsite2`), сайт будет по адресу `/calcsite2/`. Переименуйте репозиторий в `StroikaCalc` в Settings. |
| Красный крестик в Actions | Откройте запуск и посмотрите лог. Чаще всего: нет `package-lock.json` (он в проекте есть) или в `package.json` сломана команда сборки. |
| Нет картинок | Убедитесь, что папка `public/images` полностью отправлена в репозиторий (в ней 21 файл). Команда `git status` не должна показывать неотслеживаемые файлы. |
| Пустая белая страница | Проверьте консоль браузера (F12 → Console). Если ошибок нет — обновите страницу с очисткой кэша. |
| Не работает публикация настроек из админки | Это отдельная настройка: нужен развёрнутый скрипт `scripts/settings-sheet-api.gs` и его адрес «…/exec» в админке. Чтение цен и настроек из Google-таблицы работает сразу. |

## Необязательно: свой домен

Если есть свой домен (например `stroikacalc.ru`):

1. **Settings → Pages → Custom domain** → впишите домен → **Save**.
2. У регистратора домена добавьте CNAME-запись на `<логин>.github.io`
   (или A-записи на IP GitHub Pages).
3. Дождитесь проверки DNS и включите **Enforce HTTPS**.

Для сайта в подпапке проекта (`/<логин>.github.io/StroikaCalc/`) адрес останется прежним,
просто к нему добавится выбранный домен.
